Weather Wardrobe

What it is
Mobile app that picks a daily outfit from your own clothes, based on the live weather
Context
Final-year individual project, BSc Computer Science
My role
Everything: research, design, build and evaluation
Platforms
iOS and Android from one codebase
View the code on GitHub

People lose time every morning choosing clothes, then feel uncomfortable when the outfit doesn't suit the weather. Weather Wardrobe takes that decision away: it checks the weather where you are, looks through the clothes you've added, and suggests an outfit with a plain-English reason for each choice.

8screens
5database tables
5feedback tags
~2,400lines of JavaScript

How a suggestion is made

  1. Find the userThe phone's GPS gives the current location, through expo-location.
  2. Get the weatherThe OpenWeatherMap API returns temperature (°C), conditions, humidity and wind.
  3. Set a warmth targetThe temperature maps to a warmth level from 1 to 5, using the scale below.
  4. Pick the clothesWardrobe items are filtered by warmth level. If it is raining, waterproof items come first.
  5. Explain the choiceA "Why these items?" panel gives the reasons, and the app warns if your shoes aren't waterproof.
  6. Learn from feedbackThe user rates the outfit out of 5 and tags it ("Too Cold", "Wet Shoes"). Each rating is saved with that day's weather.

The warmth scale

Every clothing item gets a warmth level from 1 to 5 when it's added. The app compares that with the level the day needs:

5
below 5°C
4
5–9°C
3
10–14°C
2
15–19°C
1
20°C and up

Design decisions

  • Low-effort entry. Adding an item takes a name, a category chip, a colour, a warmth tap and an optional photo. A live preview card updates as you fill it in.
  • Show the reasoning. Users trust a suggestion more when they can see why it was made, so every outfit comes with its reasons.
  • Close the loop. The feedback screen exists so the app's rules can be checked against how people actually felt that day.

What I'd improve next

  • Hash passwords (for example with bcrypt) instead of storing them as plain text, or move sign-in to a proper authentication service.
  • Use the saved feedback to adjust each user's warmth scale automatically, so someone who always feels cold gets warmer suggestions.
  • Run a structured round of user testing and report the results.

Players join an event with an Event ID, follow hints to real-world checkpoints, prove they've arrived with a photo, and climb a live leaderboard. Admins create and edit events and checkpoints, then watch progress in real time.

10points per checkpoint
2user sides: player and admin
2phone sensors: GPS and camera

My part

  • Designed the wireframes for the whole app.
  • Designed most of the admin interface: login, event list, event and checkpoint management, and the live monitor.
  • Tested the full player and admin journeys with my partner before submission.

Shared credit. My partner, Jiexin Ren, led the functional code and API integration: joining events, photo verification, scoring, the leaderboard and admin data management. The README on GitHub sets out who did what.

KingFish Epsom

What it is
Live website for a fish and chip restaurant in Epsom
Context
Real client project
My role
Requirements, design, build, testing and launch
Platform
Web, phone to desktop
Visit the live site: kingfishepsom.comView the code on GitHub

I gathered requirements with the restaurant owner and built a site that gets hungry customers from search to ordering as quickly as possible: a clear menu, one-tap links to Deliveroo, Uber Eats and Just Eat, reviews, and a map with directions.

5page sections
3delivery platforms linked
20responsive breakpoints
37lazy-loaded images

Design decisions

  • Order first. Ordering buttons appear in the hero and again in their own section, because ordering is the main thing a visitor comes to do.
  • A menu you can scan. Tabs split the menu by category so people on phones don't scroll through everything.
  • Accessible and calm. Screen-reader labels on controls, and animations switch off for anyone who has set "reduce motion" on their device.
